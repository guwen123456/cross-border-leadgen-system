# 工作方法：买家先行，需求反推工厂

这套系统的核心不是工具，是顺序。

## 为什么买家先行

新手常犯的错：先找工厂比价，再拿着价格去找买家。问题是买家对价格的了解不比你少，
只拼价格你没有任何信息优势。正确顺序：

1. **先采集并核验买家**：公司主营、在售品类、官网真实性、公开商务联系方式，
   按 `templates/scoring.md` 的 100 分制打分，≥60 才深挖，打分理由必须写明依据。
2. **首信不报价、不推型号**：只卖四件价格之外的事 —— 逐型号核验认证文件、
   出货前质检、多型号拼单小试单、定制包装；每封信只问对方三个问题：
   主卖的价格带、市场要求的认证、可接受的试单量。
3. **买家回复 = 真实需求单**：拿着具体规格再去反向询工厂，工厂面对的是订单机会，
   不是又一份泛询价。工厂名单事先备好当备用货源池即可。
4. **供应商核验用硬项一票否决**：认证文件与具体型号对不上、阶梯价没有有效期、
   售后责任说不清 —— 任一不过直接淘汰，不看价格多低。
   实战中曾有目标买家被查出处于破产程序，直接排除出首轮名单：公开信息核验的价值就在这里。

## 质量门（脚本固化在 pipeline/ 里）

- 分数 ≥60 没有打分理由 → 不合格，打回
- 有联系方式没有出处 → 不合格
- 品类是否在售只能填 Yes / No / Unknown，**不许猜**；不是 Yes 的，信里不许声称对方在卖这个品类
- 没有针对这家公司的事实钩子 → 信不生成，宁可不发
- 跨批次合并必须去重（域名 www/https/大小写写法不一致是重复的主要来源）

## 发送纪律

- 按收件人时区分波发送，让邮件落在对方工作日上午；每波设上限，新账号更慢
- 全部逐封人工审核后发送，不群发；发送、回复、跟进都记进 outreach_log
- 只用对方在官网公开的商务联系方式；对方说不需要，立即停止联系

## 边界

本系统只处理公开商务信息，不采集私人邮箱、不用任何绕过平台规则的手段。
名单是「线索 + 核验记录」，不是成交保证：回复率取决于品类、市场和报价本身。
